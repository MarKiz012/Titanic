# Журнал экспериментов

Таблица заполняется по мере запусков. Цифры берутся из `outputs/<запуск>/metrics.json`,
поле `oof`. Leaderboard — после отправки `submission.csv` на Kaggle.

## Сравнение моделей

Все строки — 5-фолдовая стратифицированная CV, `seed=42`, признаки из
`add_features`. Leaderboard заполняется после отправки на Kaggle.

| Дата | Модель | Кодирование | OOF accuracy | ± по фолдам | OOF roc_auc | Leaderboard | Комментарий |
|---|---|---|---|---|---|---|---|
| 2026-09-16 | rf (500, leaf=2) | ordinal | **0.8339** | 0.019 | 0.8845 | | лучший baseline |
| 2026-09-16 | histgb | ordinal | 0.8305 | 0.020 | 0.8762 | | log_loss хуже — переобучается |
| 2026-09-16 | logreg | onehot + scale | 0.8238 | 0.016 | 0.8726 | | самый стабильный по фолдам |

Разница между строками (0.005–0.010) меньше разброса по фолдам (~0.019),
так что говорить о победителе рано — нужны либо новые признаки, либо
подбор гиперпараметров.

Команды, которыми получены строки:

```bash
python main.py train --set model.name=logreg --set features.encoding=onehot --set features.scale=true
python main.py train --set model.name=rf
python main.py train --set model.name=histgb
python main.py train --set model.name=lgbm
python main.py train --set model.name=xgb
python main.py train --set model.name=catboost
```

## Как читать результаты

**OOF accuracy** — главная метрика для сравнения: она посчитана на всех строках
train, каждая из которых предсказана моделью, её не видевшей.

**Разброс по фолдам** (печатается как `± std`) важнее, чем кажется. Если разброс
0.03, то разница между двумя моделями в 0.005 — шум, а не улучшение.

**Leaderboard может быть ниже CV** — это нормально: в тесте другие люди и всего
418 строк, так что одна ошибка стоит 0.24%. Тревожно, когда разрыв большой
(>0.05): обычно это переобучение или утечка в признаках.

## Наблюдения

Сюда — что реально сработало и что нет. Например:

- логистической регрессии нужны `encoding=onehot` и `scale=true`, иначе она
  заметно слабее деревьев;
- бустинги на 891 строке легко переобучаются: небольшая глубина и меньше
  деревьев часто лучше «сильных» настроек;
- на Titanic разница между хорошими моделями обычно в пределах 0.01–0.02 —
  больше выигрывают признаки, чем выбор алгоритма.
